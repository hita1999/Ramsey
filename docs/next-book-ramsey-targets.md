# 次に狙う Book Ramsey 数

調査日: 2026-08-12（JST）

## 結論

次の第一目標は

\[
22 \le R(B_4,B_7) \le 23
\]

とする。22頂点で、色1の `B4` と色0の `B7` を同時に避ける彩色を1個見つければ、既知上界と合わせて
`R(B4,B7)=23` が決まる。見つからないことだけでは `R(B4,B7)=22` の証明にはならない。

ユーザー確認済みの `R(B4,B6)=22` は未決定候補から除外する。これは Radziszowski の
2026年版サーベイ Table IXa の値とも一致する。

## 情報源と更新差分

- Radziszowski, *Small Ramsey Numbers*, revision #18, 2026-04-24, Section 5.3,
  Tables IXa/IXb: <https://www.combinatorics.org/ojs/index.php/eljc/article/download/DS1/pdf/0>
- Lidický, McKinley, Pfender, Van Overberghe, *Small Ramsey numbers for books,
  wheels, and generalizations*, EJC 32(4), 2025, #P4.64:
  <https://doi.org/10.37236/13577>
- Wesley, *Lower bounds for book Ramsey numbers*, Discrete Mathematics 349 (2026),
  114913: <https://doi.org/10.1016/j.disc.2025.114913>
- Rousseau and Sheehan, *On Ramsey numbers for books*, Journal of Graph Theory 2
  (1978), 77-87: <https://doi.org/10.1002/jgt.3190020110>
- Dai and Lin, *Book Ramsey numbers via algebraic constructions*, arXiv:2606.07214v1,
  2026-06-05: <https://arxiv.org/abs/2606.07214>
- Kalfus and Lidický, *An automated proof that R(B_8,B_10)=37*,
  arXiv:2606.05629v1, 2026-06-04: <https://arxiv.org/abs/2606.05629>

revision #18 より後に2026年6月のプレプリントが2本あるため、Table IXa をそのまま
「現在値」として扱わない。現時点では次の更新が必要である。

- `R(B8,B10)>=37` は Kalfus--Lidický により `R(B8,B10)=37` とされた。
- Table IXa の `R(B7,B9)>=33` と、Dai--Lin の
  `R(B_{n-2},B_n)<=4n-3 (n>=3, n!=6)` に `n=9` を代入した上界33を合わせると、
  `R(B7,B9)=33` となる。これは2資料を組み合わせた推論である。
- Table IXa は `R(B5,B7)>=25` と表示する一方、2025年の #P4.64 は上下界が一致した
  `R(B5,B7)=25` としている。候補選定では査読済み一次資料の確定値を採用し、未決定候補から外す。

Dai--Lin と Kalfus--Lidický は、調査時点では arXiv v1 である。プレプリント以降の
査読版、訂正、さらに新しい未収録結果の有無までは断定しない。

## 優先順位

### 1. `R(B4,B7)`

| 項目 | 内容 |
| --- | --- |
| 現在の範囲 | `22 <= R(B4,B7) <= 23` |
| 23を決める構成 | 22頂点の `(B4,B7)` 回避彩色 |
| 22を決める方法 | 22頂点の全彩色に対する非存在証明（SAT/証明書、または数学的上界） |
| 意義 | ギャップが1で、必要位数も候補中最小。現在のブロック循環探索を直接適用できる |
| 主な出典 | 2025年 #P4.64 Table 1（下界22、上界23）、2026年 survey Table IXa |

既存リポジトリには21頂点の3ブロック構成
`generatedMatrix/circulantBlock/cir21B4B7/C1toC6_227.txt` がある。
独立検証器で再確認した結果は、色1の最大bookが3、色0の最大bookが6であり、
`R(B4,B7)>=22` の証拠になっている。コミット履歴では 2024-01-27 の `caf49f9` で追加された。

一方、22頂点の `B4,B7` について、単一循環・2ブロック対称・2ブロック非対称を
完走した記録や成功構成は現行リポジトリから見つからなかった。後述の `B4,B6` の
22頂点探索は、色0側により厳しい `B6` 回避を課しているため、`B4,B7` 用に再探索が必要である。

### 2. `R(B4,B9)`

| 項目 | 内容 |
| --- | --- |

### 3. `R(B7,B11)`

| 項目 | 内容 |
| --- | --- |
| 現在の範囲 | `37 <= R(B7,B11) <= 38` |
| 38を決める構成 | 37頂点の `(B7,B11)` 回避彩色 |

## 既存探索・再現ベースライン

### 手元で再実行した軽量探索

| 対象 | 位数 | 構成族 | 探索空間 | 結果 | 実測時間 |
| --- | ---: | --- | ---: | --- | ---: |
| `B4,B6` | 22 | 単一循環 | `2^11 = 2,048` | 全探索、なし | 3.0189秒 |
| `B4,B6` | 22 | 2ブロック非対称 | `2^21 = 2,097,152` | 全探索、なし | 3.4931秒 |

これらは `R(B4,B6)=22` と矛盾しない。22頂点の一般彩色に回避構成は存在せず、かつ
今回の陰性結果はそれ自体では一般の非存在証明ではない。固定費（Numbaコンパイル・
プロセス起動）が大きいため、2,048候補と約210万候補の壁時計時間を単純比較しない。

### `R(B6,B8)=29` の環境間再現

28頂点の2ブロック非対称探索で、同じ候補番号 `1499446` と同じ3本の coloring vector を
手元PCと無料Colabの両方で再発見した。構成は
`generatedMatrix/circulantBlock/cir28_B6B8/C1C2C3_asymmetric_1499446.txt` と
`decidedRamseyNumber/R(B6_B8_28).txt` に保存されている。

| 環境 | 実測時間 | 論文環境比 |
| --- | ---: | ---: |
| 2024年論文の実験環境 | 32.15秒 | 1.0倍 |
| 手元PC | 178.9792秒 | 約5.6倍 |
| 無料Colab（1物理コア、2論理CPU相当） | 1292.9658秒 | 約40.2倍 |

Colabの進捗表示が手元PCと異なる位置で `found` になったのは、multiprocessing の
タスク完了順が異なるためで、候補番号と構成自体は一致している。

ただし旧スクリプトが表示する `1499446` は探索位置ではなく、3成分の番号の積
`26 * 571 * 101` であり、一般には衝突し得る。新しい探索基盤では3成分のビット列を
連結した一意な候補番号 `54599141` を使い、この番号から保存済み行列を完全再現する
回帰テストを追加した。過去ログとの照合には旧番号だけでなく3本のvectorも必要である。

### 2024年論文結果表から得た規模感

会話で添付された論文結果表から転記した成功探索の代表値である。現状、これらを
機械可読なベンチマーク記録として保存する仕組みはリポジトリにない。

| 決定値 | 探索空間 | 論文実測 |
| --- | ---: | ---: |
| `R(B3,B6)=19` | `2^17` | 1.65秒 |
| `R(B6,B8)=29` | `2^28` | 32.15秒 |
| `R(B8,B8)=33` | `2^32` | 152.93秒 |
| `R(B9,B10)=39` | `2^37` | 10時間26分22秒 |
| `R(B10,B11)=43` | `2^41` | 119時間51分30秒 |
| `R(B12,B13)=51` | `2^37` | 3時間13秒 |

同じ `2^37` でも所要時間が大きく異なるため、指数だけでなく、位数、Book判定の
早期打ち切り率、構成族、並列方式、JITコンパイルを含むかを記録する必要がある。

## 第一目標で埋めるべき探索範囲

### 新探索基盤の試走

2026-08-12に、追加した異サイズ2ブロックfactoryとnear-miss評価器を使い、
22頂点を10+12に分割した構成族の先頭20万候補 `[0, 200000)` をPython 3.13で探索した。

| 対象 | 分割 | 範囲 | worker | 結果 | 最良near-miss | 時間・速度 |
| --- | --- | ---: | ---: | --- | --- | --- |
| `B4,B7` | 10+12 | `[0, 100000)` | 1 | なし | 違反背表紙56、最大book `(4,10)` | 22.51秒、約4,442候補/秒 |
| `B4,B7` | 10+12 | `[100000, 200000)` | 4 | なし | 更新なし | 10.76秒、約9,295候補/秒 |

この構成族全体は `2^23 = 8,388,608` 候補である。最初の10万候補の後、同じcheckpointを
使って4 workerで正常に再開できることも確認した。結果JSONとcheckpointは
`generatedMatrix/_runs/` に保存したが、環境固有の一時成果としてGit管理から除外している。
これは探索基盤・異サイズ構成・スコア保存・並列再開が一体で動くことを確認する試走であり、
10+12構成族を完走した結果でも、一般の22頂点彩色の非存在を示す結果でもない。

`R(B4,B7)` の22頂点について、少なくとも次を別々のジョブとして記録する。

1. 単一循環を全探索する。
2. 2ブロック対称非対角を全探索する。
3. 2ブロック非対称非対角を全探索する。
4. 11+11以外の構成を扱う場合は、分割と自由変数数を明記する。
5. 既存21頂点3ブロック構成からの1頂点追加・辺再彩色を試す。
6. 失敗時は「一般に不存在」ではなく、構成族、範囲、コミットSHA、環境、候補数、
   探索時間を伴う陰性結果として保存する。
7. 成功時は探索実装とは独立な検証器で最大bookを再計算し、完全行列とSHA-256を保存する。

`R(B4,B7)` の単一循環と2ブロック探索が陰性なら、次は同じ22頂点の SAT/局所探索を
優先する。`R(B4,B9)` へ移るのは、第一目標の構造化探索を一通り記録した後とする。
